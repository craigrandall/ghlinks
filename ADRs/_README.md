# About ghlinks Architecture Decision Records (ADRs)

A few general notes about the Architecture Decision Records (ADRs)
contained in the top-level `ADRs` folder of the `ghlinks` GitHub repo:

- They are version-controlled already; so, their filenames should be free
  of date and version markings.
- Links to other content/context are encouraged within an ADR. Be sure
  that what you specify is generally, not just specifically (e.g. to your
  local env), findable (e.g. relative paths within this repo).

---

## Fundamental qualification as an ADR

**An architecture decision is a choice that (a) is expensive or
disruptive to reverse, (b) constrains later work across components, and
(c) had genuine alternatives a reasonable engineer would weigh.**

## ADR template

*(Copied from https://github.com/adr/madr/blob/develop/template/adr-template.md,
which should be treated as the official template)*

See `adr-template.md` in the same folder as this README.

For your new ADR, make a copy of this template and fill it out
completely. Give it a file name that is as concise as possible while
reflecting the internal purpose line of the ADR, guided by the template's
built-in guidance.
